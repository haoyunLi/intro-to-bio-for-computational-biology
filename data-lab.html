02 / RNA EXPRESSION

count 翻倍，表达就翻倍了吗？

同一小型矩阵切换 raw count 和简化 CPM。本题三行包含全部纳入演示的 gene count（Other genes 为合并行），所以 CPM = gene count ÷ 三行 count 合计 × 1,000,000；真实文件须核对分母定义。

feature / gene样本 A样本 B
纳入 gene counts 合计1,0002,000

读数背后的实验

本题只聚焦 Gene X：它的 raw count 翻倍，可由文库总量翻倍解释。表中其他 gene 的比例未必不变；请逐行检查。真实 RNA-seq 还要考虑组成偏差、基因长度、组织细胞混合、生物重复和流程版本。CPM 也不是差异表达的完整统计模型。

raw count、TPM、log1p 和模型内的 normalized count 不能在图注里统称“expression”。

03 / GENOMIC COORDINATES

同一个碱基，为何坐标差一？

输入虚构 contig 上的单碱基 VCF POS，看它在 BED 区间规则下怎样表达。本题只演示坐标，没有真实基因组 build，也未核对 REF/ALT。

四项都要记

  1. Build：例如 GRCh38。
  2. 命名：chr7 还是 7。
  3. 规则：VCF POS 1-based；常见 BED 左闭右开且 start 0-based。
  4. Allele：REF / ALT 是否与参考匹配。

05 / SEQUENCING BY SYNTHESIS

测序仪的一轮 cycle 在读什么？

以常见 Illumina SBS 为概念模型。模板按 3′→5′ 写为 T-G-C-A-T-G；点击下一轮，看新合成链按 5′→3′ 延长。荧光检测与解除阻断是每轮的关键步骤。

  1. 1 · 加入互补碱基
  2. 2 · 成像读出信号
  3. 3 · 解除阻断

播放速度为教学设定；高亮表示当前步骤，色彩不对应真实化学版本的荧光通道。

它简化了什么？

真实 flow cell 同时读取大量 cluster；不同化学版本的荧光通道编码也不同。这里展示“加入互补碱基 → 成像 → 解除阻断”，不模拟仪器误差和 index read。

得到的 read 还需质量评分、样本拆分、比对与定量，才能进入 gene count。

06 / FASTQ → ALIGNMENT → GENE COUNT

一条 read 如何变成 count？

从测序仪的四行 FASTQ 记录开始，依次经过碱基质量 → 参考比对 → 基因注释 → 计数。先预测三条虚构 read 的命运；答对后才展开完整路径。末尾看一个很小的 gene count 表。

TOY MODEL · 单端、精确匹配

教学参考片段 · 不是人类真实序列

注释到哪个 gene可匹配的参考片段
Gene AACGTTACA · GGAATCCG
Gene BTTGACCGA · GGAATCCG
本题规则：每个碱基 Q ≥ 20 才继续；短序列只按完全相同匹配；恰好归到一个 gene 才给它 +1。这里每条 read 只有 8 个碱基，仅供教学；真实流程由文库、软件和参数决定。

当前 FASTQ 记录 · 四行分别是 ID、碱基、分隔符、逐碱基质量
先预测：按上面的教学规则，这条 read 最后怎样进入 count 表？
    五个容易混淆的词
    1. Read：测序仪报告的一小段序列，不是一整个基因。
    2. FASTQ：一条 read 的碱基与每个碱基的质量符号；本题 I 对应 Phred+33 的 Q40，! 对应 Q0。
    3. Base quality：碱基调用可能出错的估计；它来自测序阶段。
    4. Alignment：把 read 与参考序列比较；一个 read 可有多个候选位置。
    5. Gene annotation：把位置连接到 Gene A/B。SAM/BAM 中的 MAPQ 是定位不确定度，和 FASTQ 的逐碱基 Q 不是同一列。
    真实 GDC mRNA 流程用 STAR 生成 gene-level raw counts；官方文档说明，映射到多个不同 gene 的 reads 不进入其 STAR 计数。我们的 8 个碱基精确匹配和 Q20 拒绝规则只用于直观教学；真实比对、剪接、paired-end、过滤与计数更复杂。

    07 / RNA NORMALIZATION
    同一张 count 表，为什么有五种数字？
    三种虚构基因、两个样本。A/B 的 raw 不变，只有 C 增加。切换尺度，看文库总量、假设长度及组成变化分别怎样影响数字。
    
      
    gene假设长度样本 S1样本 S2
    纳入 gene counts 合计—1,0002,000
    读这个表的方法
    1. Raw：reads/fragments 经比对和定量流程分配到 gene 的计数，并非直接的 RNA 分子数。
    2. CPM：只校正文库总量。
    3. RPKM/FPKM：再考虑基因长度；R 与 F 要按 read/fragment 区分。
    4. TPM：本题三行覆盖全部纳入的 feature；先按长度缩放，再使未四舍五入的三行总和为一百万。
    5. size factor：示意 DESeq2 的相对规模估计，不是 p 值或差异表达结果。
    本例只有 3 个基因、无生物重复；为演示 RPKM/FPKM，还假定三行计数合计等于用于分母的 mapped reads/fragments 数。真实文件要核对 feature 集合、长度和分母定义，不能把这个玩具矩阵当统计分析。

    08 / ZERO, MISSING OR INVALID?
    空白格一定要填 0 吗？
    四份虚构记录分别代表：已测但 count=0、panel 没有测、文件 QC 失败，以及状态未知。先读原始证据，选择进入分析表时应如何处理，再看理由。0、NA、排除、核查代表四种不同状态。
    
      
    target × sample → analysis_value
    原始证据字段这份记录
    进入用于比较基因表达的分析表时，你会先怎样处理这一格？
    为什么一个空格有四种含义？
    1. 已测的 0：保留数值 0，同时保留流程与质量信息；不把 0 宣称为分子绝对不存在。
    2. Panel 未测：目标不在检测范围，应记为未测的 NA；填 0 会伪造一次阴性观测。
    3. QC 失败：该文件暂不进入本次定量比较，保留 QC 失败原因，必要时重做或重新处理。
    4. 状态未知：先查 panel、原始文件与 QC 报告，再决定是 0、NA 还是排除。
    真实 GDC RNA 流程说明：有些完全被其他基因覆盖的基因，因为 reads 无法唯一分配，可能显示 0。真实 Xenium 输出包含 gene_panel.json；先用它确认目标基因是否在 panel 内。

    09 / SPATIAL SEGMENTATION ERROR
    点没有移动，为什么 cell×gene 矩阵变了？
    十个虚构 RNA 检测点保持原坐标，只改变估计细胞边界。观察核轮廓、5 µm 扩张、过度扩张和配准错位怎样造成漏分、错分与细胞外点误纳入。
    
      
    正确归属
    错分到别的细胞
    真实细胞内但漏分
    细胞外点误纳入
    当前 cell × gene
    geneCell ACell B
    播放速度只用于教学。虚线 true boundary、点位和数值都是本站构造的 toy data；它们不是 Xenium 的真实算法输出或精度基准。
    分割误差怎样进入数据？
    1. 漏分：边界太小，细胞质 RNA 没有 cell ID。
    2. 错分：相邻边界重叠或偏移，同一点可能进入另一颗细胞。
    3. 误纳入：边界太大，细胞外点被计入 cell×gene 矩阵。
    4. 下游传播：细胞类型、空间邻域和差异表达都会继承这些归属决定。
    10x 当前文档说明 Xenium 的细胞轮廓可能来自 boundary stain、RNA stain 边缘或核扩张；技术说明给出的默认各向同性核扩张距离为 5 µm。分析时应记录软件版本、分割方法和质量字段，并在图像上抽查边界。
